## Requirements

### R1. P0 Defect Remediation
Implement production-grade fixes for all six verified P0 issues:
- **P0.1 Recovery Barrier Validation Before Truncation & TOCTOU Prevention:** Acquire the shared recovery lock before trusting or acting upon Recovery Barrier contents. Re-read the Barrier under the lock, then validate its schema (required fields, exact types, identifier formats, digest format, state values, non-negative offsets, record counts, cross-field consistency) and verify the digest using constant-time comparison before trusting values. All subsequent Commit Chain verification (offset within file, physical frame boundary, record count, target generation existence and validity), Snapshot validation, and Manifest verification must occur while continuously holding the same recovery lock through truncation, durability flush & fsync, post-truncation chain re-reading and verification, and state transition. Fail closed on any mismatch, preserving the original Commit Chain.
- **P0.2 RFC 8785 Canonical JSON & Historical Cryptographic Compatibility:** Remove custom float formatting (`f"{o:.15g}"`). Use a pinned, trusted RFC 8785 library for canonical JSON serialization, rejecting NaN, Infinity, -Infinity, and invalid representations. Fail closed if unavailable with no non-compliant fallback. Introducing RFC 8785 must not silently rewrite historical Commit Records, Manifest files, or existing cryptographic hashes. Establish explicit compatibility verification for historical records. If an existing record cannot be validated under its original documented rules, fail closed and preserve the original data. Any migration must be separately designed, auditable, and explicitly authorized.
- **P0.3 Centralized Windows ctypes Safety:** Implement a centralized Win32 API wrapper (`argtypes`, `restype`, `HANDLE`, `DWORD`, `BOOL`, structure definitions) covering `CreateFileW`, `GetFileInformationByHandle`, `CloseHandle`, preventing 64-bit handle truncation. Ensure deterministic handle ownership, guaranteed handle closure on both success and failure, immediate `GetLastError` capture, and fail-closed identity verification.
- **P0.4 Administrative Barrier Clearing:** Validate Commit Chain, active generation, active pointer, Manifest, and Snapshot under shared recovery/publication lock before clearing Barrier. Record a persistent audit record (Actor ID, UTC timestamp, reason, barrier ID, previous state, verified generation, chain/snapshot results, decision) flushed and fsynced prior to Barrier removal. Transition to READY only after successful revalidation.
- **P0.5 Atomic Generation Publication, Explicit Commit Point & Orphan Reconciliation:** The selected publication protocol must formally define its linearization/commit point, durable ordering, crash states before and after commitment, recovery behavior, and idempotent orphan reconciliation. Evaluate atomic directory rename vs durable publication journal for Windows and POSIX; demonstrate crash consistency at every publication boundary on the actual target platform without equating single file replacement with multi-artifact generation publication. Handle orphan reconciliation (incomplete directories, SQLite without Manifest, Manifest without SQLite, inactive generations, active pointer referencing incomplete generations) without activating incomplete generations or leaking resources.
- **P0.6 SQLite Semantic Integrity & Cross-Artifact Binding:** Enforce physical integrity (`PRAGMA integrity_check`, `PRAGMA foreign_key_check`), schema verification via fingerprinting (tables, columns, types, keys, indexes, triggers), semantic entity count validation against Manifest (skills, aliases, domains, subcategories, relationships), cross-artifact cryptographic binding (Commit Record <-> Manifest <-> Snapshot), and type-specific relationship semantics.
